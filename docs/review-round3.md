## 3. 제안: 3단계 "Mission control" (위성 조작)

원칙은 그대로 유지: **사용자가 명령하고, CRIC가 계산하고 검사하고, 사람이 확정**. 실제 위성에 보내는 것은 없음. 기존 코드(`physics/maneuver.py`의 CW 전파·`rescreen`, `physics/drag.py`, `launch/sun.py`, 통과 계산)를 재사용.

| # | 기능 | 사용자가 하는 일 | CRIC가 하는 일 | 재사용 | 크기 |
|---|---|---|---|---|---|
| C1 | **수동 분사(burn) 콘솔** | 시각, 방향(진행·반경·법선), 크기(m/s)를 슬라이더로 입력 | 새 궤도 계산, 지구본에 이전/이후 궤도 겹쳐 표시, 카탈로그 72시간 재검사, 추진제 잔량 차감. 위험하면 "이 분사는 X와 1.2 km 근접을 만듭니다" 경고 + 더 안전한 대안 제시 | `rescreen`, CW, `trajectory_series` | 중 |
| C2 | **촬영 예약** | 지도에서 촬영 지점 클릭 | 다음 통과 중 촬영 가능한 것(태양 고도, 시야 각도) 목록, 예약하면 타임라인에 표시 | 통과 계산, `sun_elevation` | 소~중 |
| C3 | **시간 빨리감기 + 실시간 위치** | ×1/×60/×600 재생, 타임라인 스크럽 | 내 위성 위치·지상 궤적·다음 이벤트(통과, 촬영, 조우) 카운트다운 | SGP4, 지구본 | 소~중 |
| C4 | **고도 유지·수명·폐기** | "고도 유지" 또는 "임무 종료" 클릭 | 대기 저항으로 고도가 얼마나 빨리 떨어지는지, 재상승 분사 필요 시점, 폐기 분사 후 재진입까지 기간(규정 5년 이내인지) | `drag.py` | 중 |
| C5 | **명령 기록** | (자동) | 사용자 명령·CRIC 검사 결과·승인이 해시 체인 로그에 남음 | 기존 승인 로그 | 소 |

추천 범위(남은 시간 고려): **C1 + C3 + C5를 먼저**, 시간이 남으면 C2 → C4.
C1이 핵심인 이유: 사용자가 직접 위험한 선택을 할 수 있고, CRIC가 그걸 잡아내는 장면이 영상에서 "AI가 사람을 돕되 결정은 사람이" 메시지를 가장 잘 보여 줌(J1, J9, U1 동시 해결).

영상 반영 예(3단계, 약 20초): 사용자가 촬영 각도를 좋게 하려고 고도를 낮추는 분사를 넣음 → CRIC: "이 분사는 내일 03:12에 다른 위성과 900 m 근접" → 대안 제시(시각 4분 늦추기) → 사용자가 대안 선택, 승인.
